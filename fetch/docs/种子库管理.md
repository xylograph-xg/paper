# 种子库管理

种子库是后续搜索的基准。精读库中非勘误文献新增“设为种子”；点击后立即保存种子身份，并独立排队一次该论文的关联检索。后续全通道检索继续读取当前全部种子，展开它们的参考文献、引用论文及相关主题，保持只接收实际获取并校验PDF的规则。

种子身份与阅读决定分开：设置或移除种子不改变原文、卡片、精读状态、历史候选顺序与自动制卡配额。种子页显示“检索种子”标记，勘误显示“关联勘误”；勘误不作为展开搜索的基准。更多操作中可“移出种子库”，取消尚未开始的自动种子展开任务，正在执行的任务不打断。退出后元数据补全及初始种子登记不会把它重新选回。

## 当前运行实例的兼容

新实例支持 POST /api/seed {id,enabled}。保持当前工作台和worker运行的情况下，前端在旧实例返回404时复用原来受token/Origin保护的 POST /api/discover {seed_id,seed_action}。

数据库迁移安装兼容触发器：种子操作写为已完成seed_control记录及human_seed_change审计；另按论文ID排队关联discover任务。繁忙的全局discover不会吞掉种子管理操作。来源补全对显式种子身份的保护同时在SQLite层生效，现有已加载Python进程无需停止或重新加载。

## 验证

52项离线测试通过，覆盖精读记录与资产保留、繁忙检索时操作可靠、重复加入不重复排队、移除取消未开始任务、移除后不被元数据补全恢复、勘误/普通未精读候选不能设为种子、检索使用全部选择种子并排除勘误。

隔离HTTP临时数据库验证：新接口、旧接口兼容、繁忙检索、无token请求403通过。浏览器使用模拟写请求验证精读库设置→种子库显示→移除完整流程，无JS错误；未代用户把任何真实文献选为新种子。

当前实例已安装数据库兼容迁移。重新加载网页即可出现新按钮，后台无中断。
