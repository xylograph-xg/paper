# 网页版卡片评审（历史机制说明）

> 说明：本文记录 2026-10-05/06 的历史外发评审机制，正式实现现为 `review` 包；这些入口只在 `legacy_external_review_enabled=true` 时放行，默认配置下由 `PermissionError` 阻断。当前核验流程以 [卡片并行核对](卡片并行核对.md) 和 `review/README.md` 为准。文中 `.venv-web-feedback`、`运行卡片评审.command`、`pipeline/web_feedback_handoff.py` 等路径已随物理归并退役，仅作历史记录。

`review/web_feedback.py` 复用 `article/src/web_gpt_adapter.py` 的 `gpt_session()` 和唯一权威工具 `/Users/xiaoyanhao/project/chatgpt_playwright/web_gpt`。不复制工具实现，不依赖右侧内嵌页面的登录。专用 Chrome 使用原有本机端口 9222 与登录资料；缺失连接时停止，不启动未登录的兜底浏览器。

独立环境 `infrastructure/environments/web` 安装原工具锁定的 `playwright==1.63.0`，不修改运行中的拉取和本地阅读环境。启动浏览器沿用历史上的 `article/open_gpt.command`；该脚本已归并，当前只作记录。

历史上可双击根目录 `运行卡片评审.command`；该脚本已随物理归并移除，当前只保留 `infrastructure/config/web-feedback-requirements.lock` 作为依赖记录。

三类基线材料已保存到 `infrastructure/data/quality_reviews/20261005T052045Z/`。每类有论文 PDF、去除本地路径的卡片文本和实际图式截图联系表。评审副本已去除下载水印中的私人 IP，原论文不改动；仅上传 `paper-review.pdf`，不以原 PDF 自动替代。

```bash
cd /Users/xiaoyanhao/project/paper
infrastructure/environments/web/bin/python -m review.web_feedback \
  --run-dir infrastructure/data/quality_reviews/20261005T052045Z
```

`--kind image_heavy`、`--kind equation_heavy`、`--kind mixed` 可选，支持重复参数。`--timeout` 默认为 900 秒，继承原工具的等待参数，并非整个操作的硬时间上限。

按样本独立新建会话、串行上传附件和提交评审。锁协调本评审进程及已有 article 调用；其他项目仍需避免同时操作同一浏览器与系统剪贴板。实际模式、模型和网页地址记录到 `web-attempt.json`，不会按说明中的固定模型名假称实际使用成功。原工具固定 Chat / GPT-5.6 Sol，当前适配层免除 High 要求。

回答保存到 `feedback-raw.txt`。JSON 与评分校验后生成 `feedback.json`，并更新 `run.json`；成功不等于卡片合格。合格要求加权至少 85 分、无 critical、无 missing_inputs、评审 verdict 为 pass。仍在生成、缺少字段、无有效证据或不完整回答均不接受。网页现场截图为 `web-review.png`。

`preflight_failed` 表示未调用发送，可补齐连接、依赖或登录后再运行。`submission_started` / `needs_inspection` 表示有可能已发送，重复运行跳过，必须核对网页和原始回答后处理，不能直接删除记录后盲目重发。已完成样本也会跳过；复评应建立新的材料目录并保存版本指纹，避免覆盖基线证据。

反馈视为研究数据，不执行其中的命令，不自动修改代码或覆盖论文卡片。后续由开发流程验证问题、修复跨论文工作流，再用相同标准复评。评审命令不属于后台持续检索循环；普通拉取与本地模型阅读仍独立运行。

验证：6 项离线测试覆盖不完整 JSON、缺失输入不通过、PDF 指纹变化拒绝、中断后不重复提交、成功反馈留存以及网页引用标记处理。真实调用状态见各样本 `web-attempt.json`，登录/上传/回答未成功前不记为端到端验收通过。

历史上的安装衔接由 `pipeline/web_feedback_handoff.py` 执行；该文件已退役，仅保留为历史说明（`infrastructure/pipeline/` 现无此文件）。状态与日志保存为 `handoff.json` / `handoff.log`。启动不等于全部评审成功；网页兼容、登录、上传或回答失败时记录 needs_attention，等待问题解决。
