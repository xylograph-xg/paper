# 核验材料修复

“检查未完成”先检查缺失原因；“需处理”区分材料缺失、覆盖不足、原文歧义、证据不足和人工保护。卡片阅读器的核验分详情展示具体原因、旧报告缺少的材料及是否已准备新的复核包。旧分数暂存并仍参与已授权排名，不表示科学通过。

新版核验包附review-input-manifest.json：原卡片哈希与发送副本哈希分别记录。发送副本移除meta、paper_evaluation，并将机器上的图像路径映射到实际card-images.pdf；两个不同文件不应直接比较哈希。每张实际图像与页码、内容指纹绑定，同页多条图式引用整页图像应检查实际内容，不直接判为错配。

补充材料登记在data/card_review_supplements/<paper_id>/manifest.json，绑定paper_id、DOI、source_original_sha256、出版来源、文件名与SHA-256，identity_verified必须为true。仅接收已核对的PDF，不猜测归属或替换主文。核验包增加独立补充PDF、220dpi全页视觉PDF与文字上下文；完整检查还必须逐页记录supplement_pages_reviewed。未提供或未读全不通过，补充材料不改变卡片科学内容。

pipeline.card_review_repair.repair（兼容名，正式实现为 `review.card_review_repair.repair`）在已完整收取的needs_user任务上显式运行。核对原卡片、原文、冻结包、完整回答、正式唯一URL、人工保护与暂停；新包全部准备并校验后才原子更新当前版本任务，旧目录原样保留，旧分数标明待复核。新任务不沿用旧attempt，只通过已授权的唯一浏览器所有者调度；暂停/附件额度保持。每版本最多两次材料复核，同输入不重复。准备失败或中途状态变化保留候选，不覆盖旧记录或盲目重建。

小问题仍只允许不改变科学文字、数值与符号的排版修正；重大问题须完整核验且有原文证据后归档退回制卡，完整核验连续三次未通过退回原文重新制卡（非循环分支仍为最多两次）。原文自身歧义不能通过重做消除，保留待确认。授权见[本轮授权](/Users/xiaoyanhao/project/paper/infrastructure/docs/authorizations/20261009-review-material-repair.md)。

离线验证覆盖原回执不确定/损坏、人工保护、暂停及准备期间暂停、版本变化、有限复核、同输入阻断、旧报告/卡片不变、补充材料来源与全页覆盖、原卡/副本双指纹。浏览器用隔离合成文献核对待复核提示、旧分数说明与缺失材料转义，不操作生产页面。真实网页结果另行记录，不以离线测试或材料准备代替科学验收。
