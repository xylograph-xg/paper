# 局域网查看卡片兼容修复

2026-10-08。用户从远程电脑经局域网 HTTP 链接打开文献工作台，原文可读，点击查看卡片报 `crypto.randomUUID is not a function`。

## 原因与修改

卡片的 Markdown 渲染先生成临时标记来保护公式，原实现直接调用 `crypto.randomUUID()`。该方法仅在安全上下文提供；普通局域网 HTTP 不满足条件，本机回环 HTTP 则可用。因此卡片在正文渲染阶段中断，直接打开 PDF 不经过这段代码。

`workbench/workbench.html` 改为不依赖 Web Crypto 的临时随机标记，并检查标记不与输入原文冲突。它只用于当前渲染，不承担认证或安全令牌功能；公式仍保留原文并经既有安全清理、KaTeX 显示。

可选裁图的 SHA-256 核对先检测浏览器能力。HTTP 下缺少 `crypto.subtle.digest` 时继续显示原页图像与放大入口；具备能力时仍须核对 `card.json` 指纹，指纹不一致的裁图不得使用。

## 验证与使用

`tests/browser_lan_card.cjs` 使用独立临时 Chrome、本地前端资源和合成卡片，覆盖非回环 HTTP、本机回环 HTTP、HTTPS 三种来源。检查浏览器真实安全上下文和接口可用性、点击卡片、四种公式定界符、公式原文、标记冲突、原页图片、放大与 PDF 链接、重复打开、HTML 清理及裁图指纹不一致时回退。测试不连接正式制卡浏览器，也不提交文献。

实际结果：旧版在非回环 HTTP 下复现相同的 `crypto.randomUUID is not a function`；仅包含本次修改的页面在三种来源均通过，JavaScript/CSP 错误为 0。历史记录的 13 项检查涉及 `tests/test_workbench_access.py`、`reading/tests/test_card_display.py` 与 `cards/tests/test_card_image_paths.py`（跨项目用例），本次只核对文件存在性，未重新运行测试。全局接口更新与链接检查另按 all 规则执行；本次未修改登记工具接口。

工作台服务器每次请求读取 HTML，并返回 `Cache-Control: no-store`。远程电脑刷新页面后再查看卡片即可加载修改，无须重启拉取或制卡服务。

浏览器接口依据：[MDN randomUUID 安全上下文要求](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)。验证属于前端兼容测试，不构成科学内容验收；未操作用户远程电脑。
