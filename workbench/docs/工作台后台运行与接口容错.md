# 工作台后台运行与接口容错

2026-10-08。用户反馈关闭工作台启动器终端时要求确认终止程序，并在点击时遇到 `Failed to execute 'json' on 'Response': Unexpected end of JSON input`。

## 已核对原因

`启动文献工作台.command` 原本直接执行前台 `pipeline serve`。现场网页服务 PID 34029 仍附着 `ttys000`，所以关闭该终端确实可能终止网页服务；此前“运行后可关终端继续远程查阅”的说明与实现不符。独立拉取/制卡常驻服务不等于网页服务已经脱离终端。

HTTP 服务同时最多处理16个连接，容量耗尽时原本返回空正文的503。前端查看卡片等入口直接解析 JSON，能产生用户报告的空响应解析错误。代理错误或响应中断也可能表现相同；仅凭前端错误无法断言刚才具体请求的HTTP状态。

## 修改与运行边界

启动器改为 `pipeline.workbench_service`：用独立进程会话、断开标准输入、日志文件及关闭继承句柄启动网页服务，确认受认证保护的健康检查返回正确PID/端口后显示链接并退出。启动锁及服务器锁避免重复实例；旧的前台服务复用时明确提示保留原终端，不伪称已脱离。访问记录损坏时阻断启动，不覆盖原记录。

后台网页服务不初始化种子或排队、不启动工作流worker、不解除暂停；只提供工作台已有的人工操作入口。不新增LaunchAgent。网页服务日志在Catalog目录的 `logs/workbench-service.log`，访问身份在 `workbench-access.json`。同一目录、端口的明确重启保留原口令，使现有远程链接和登录会话继续可用。主机重启后需重新运行启动器；关机、断网或SSD不可用时不能继续读取对应原文。

开发CLI `python -m pipeline serve` 保留前台运行方式。普通用户通过根目录 `.command` 启动后台网页服务；脚本支持 `--config`、`--port`、`--no-browser`。

容量耗尽仍返回503和 `Retry-After: 2`，同时返回完整JSON错误、准确Content-Length、正确Content-Type和禁止缓存头。`GET /api/workbench-health` 须有效访问口令/会话，返回服务标识、PID、端口和后台标志，不返回口令，也不调用拉取、制卡或模型。

前端统一读取响应：空正文、截断JSON、非JSON代理错误显示可理解提示。查阅等GET最多额外2次，只在短暂连接/响应错误或502/503/504时重试；304继续复用状态，403等永久错误不重试。写入及启动操作不自动重试；成功状态下回执损坏或连接中断时提示先刷新核对实际状态，避免重复提交。短暂登录连接故障不删除已存口令，明确403才清除。

## 已完成验证

- 17项相关测试通过：容量耗尽完整JSON、认证健康检查、两个启动器竞争后只有一个服务、启动器退出/SIGHUP后仍可访问、重复启动PID一致、明确重启口令保持、暂停记录及空队列不变、损坏身份阻断、原文/卡片图像与指纹保护。
- 独立临时Chrome三种来源通过：非回环HTTP、本机回环HTTP、HTTPS。故障注入覆盖空503、截断200、持续空200、HTML代理502、读取重试上限、恢复后查看卡片，以及操作响应损坏只提交一次；公式、原图和放大仍可用，JavaScript/CSP错误0。
- 启动脚本和Python语法检查通过。前述测试使用临时数据库、本地资源与合成卡片，不连接正式制卡浏览器、不提交文献、不构成科学验收。

现场确认：网页服务由34029迁至51882，父进程为1、无控制终端；启动器已退出，重复运行退出0并复用相同PID。旧访问口令保持，本机和Tailscale远程健康检查均返回200，远程真实卡片接口也返回可解析的200。拉取、制卡、页面巡检所有者记录及三份暂停控制指纹在迁移前后相同。
