# 现有运行入口适配项目

这里没有文献发现、制卡、核验或修正业务实现。每个旧模块文件只把旧导入/CLI转发到其唯一真实子项目；完整映射见 [interface.json](interface.json)。公开兼容接口是 [api.resolve_legacy_module](api.py)。

为什么保留：旧导入、历史CLI和外部调用曾使用 `pipeline.*`；三个原LaunchAgent本轮已切换真实组件CLI。直接删除会让它们下次加载或启动失败。适配器绑定同一模块对象，包含已加载旧所有者的对象，不创建第二个Catalog或页面锁，不恢复暂停、不启动模型。

`__main__.py` 只转发 core CLI；`_compat.py` 只解析映射、导入和保持对象身份；其他Python文件都是单一转发入口，没有业务代码副本。新项目源码已禁止导入本项目。

原工作台服务已按本轮授权维护并读取workbench唯一资源；旧HTML/vendor部署副本在核对规范源内容及服务归属后删除。许可证在workbench/vendor保留，旧回执原字节不变。

选择兼容接口而非软链接，是为了真实目录隔离和可独立声明接口；保留历史调用合同，防止未知提交、在途上传与真实回执丢失。此项目不是新常驻入口。

检查：从paper运行 `make check`；对应模块旧CLI `--help` 与对象身份由离线测试验证。正式业务从各子项目API/CLI调用，权限仍由原控制合同决定。
