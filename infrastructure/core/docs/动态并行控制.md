# 动态并行控制

任务状态的文献拉取、网页制卡各有“并行”菜单。默认24/20；拉取可选1、2、4、8、12、16、24、32，制卡可选1、2、4、6、8、10、12、16、20。停止按钮保留原确认。

设置保存在主Catalog旁concurrency-control.json，CLI：`python -m pipeline.concurrency_control --target fetch|cards --value N`。输入必须为整数且范围合法；原子更新单项保留另一任务值。无控制文件时沿用旧配置，不影响隔离实验。改变设置不恢复暂停、不启动本地模型或切换网页模型。

下载总量分配约2/3直链、1/3回退；单路时共用同一个槽位避免回退饥饿。线程池惰性创建，claim数按当前目标限制。增加允许下一轮新增，减少保留现有future、不再补充超额任务。种子最大10、主题最大4，独立DOI游标、站点限速和Retry-After照常生效。

制卡限20并行，浏览器总页数限20，其他页面占用仍计入。新增页仅本任务明确授权的GPT首页，共享提交锁内每批最多两页，避免长时间阻塞结果收取；配置变更唤醒检查，锁忙或未补齐5秒重试。每页成功独立登记，后续页面导航失败不丢失已创建槽位；创建中的页面只有实时证实空白、无历史/草稿/请求才接管。减少只关闭本任务空白槽位或唯一URL且保存原始回答/实时哈希一致的完成槽位，不关生成、未知提交或他人页面。收取后再缩减，材料上传/发送仍串行。

并行目标不是已运行数量。没有候选、验证、额度或网络限制时保留真实状态，不能以开页数声称完成结果或科学验收。
