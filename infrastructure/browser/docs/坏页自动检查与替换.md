# 坏页自动检查与替换

2026-10-09，用户在询问固定20页中是否存在不可用页面后，明确要求“有问题自动检查，删掉再新建”。本轮授权见[坏页修复授权](/Users/xiaoyanhao/project/paper/docs/authorizations/20261009-page-health-repair.md)。替换针对本任务已登记的故障网页；原文献请求、科学卡片和模型额度仍独立保护。

## 检查和处理顺序

主 `web_cards` keeper 是唯一 CDP 所有者，在原连接和共享提交锁中检查、归档、关闭、创建和更新槽位。没有新的常驻服务，`web-tab-watch` 继续只读 HTTP 元数据并发维护请求，不自行操纵网页。

每30秒安排一次检查，在原所有者可维护时执行；上传/提交占锁时等待，不新增第二个CDP连接。每轮最多替换2页。每次处理先实时核对原 target 属于登记的专用窗口、原材料和提示指纹唯一匹配、原账本未变化，再检查生成状态、正式回答、草稿、访问验证和故障证据。旧 `needs_inspection`、超时、空白、URL 变化或按钮消失本身均不能成为删除依据。

- 页面已有正式回答时，先完整收取原回答，核对正式唯一 URL、原用户材料、提示与输入指纹、落盘回答哈希、实时正文及无生成状态。原回答保存后才能释放页面；不能为换页丢掉答案。
- 回答文件只是归档后路径失效时，先按原 target、实际页面材料、正式 URL 和原哈希定位唯一归档，恢复正确证据路径。不能把文件不存在当作没有回答，也不能用另一项较新的未发送记录替代页面实际归属。
- 明确发送前失败、原 target 有本任务账本且不存在任何未完整收取的旧请求时，可保存故障和未发送证据后替换。SSL 故障不自动绕过证书警告。
- 已发送但正式会话明确终止、没有正式回答时，本轮授权允许先归档原请求和终止证据，再替换该网页。旧文献任务不因此重新入发送队列，也不重发到替代页。
- 正在生成、未知提交、临时 `local-chatgpt` URL、材料不唯一、访问验证、身份/版本/范围不明和证据变化继续保留。自动检查不承诺把所有待核对页都删除。

“已结束且没有回答”必须有实时原会话证据和稳定复查。仅最后一个用户消息具有 `complete` 标记、页面没有停止按钮、回答数量为0，不能证明请求已经终止。证据不足仍按未知请求保留。

## 替换生命周期与崩溃恢复

`pipeline/shared_page_repair.py` 编排以下步骤，逐步保留独立回执，不能把多文件写入当作一个原子事务。

1. 在共享锁中重读控制、完整页面清单、登记、pool和原账本，确认允许维护。冻结当前槽位的新任务分配；保存原登记指纹、槽位 ID、原 target、窗口 ID、账本及材料哈希。
2. 先完整收取可恢复回答，或确认明确未发送/终止故障；保存不可变证据包和修复 journal。原回答与关键 JSON 持久落盘、校验哈希后才进入删除步骤。
3. 先记录关闭意图，再关闭精确归属的原 target。通过完整清单确认它已消失，才记录旧页已关闭。关页回执不确定时先重读事实，不立即重复关页或新建。
4. 创建替代空白页，并立即记录新 target。核对它在同一登记窗口、页面空白、无用户消息、无草稿、无生成、无登录/验证要求。创建失败或位置不可证明时保留该槽位的等待状态，不能声称已补齐。
5. 新 target 先加入 pool 的受保护准备状态，再以原登记指纹和原槽位 target 作条件核对，更新同一个 `slot_id` 的 target，记录 `replacement_history` 和 `generation/revision`。原 target 在 pool 历史中记为 `retired_replaced`，原账本和证据不删除。
6. 再次核对新 target 与登记一致、真实空白且无验证后，才标记 `ready_blank`。下一轮统一分配器可以分配新的已授权待办；不会把换页解释成允许重发旧任务。

崩溃后按 journal、登记、pool及真实页面事实恢复：已有新 target 时不重复创建；登记已更新而 pool 未就绪时继续保护；旧 target 仍在时不补出第21个专窗页；新 target 不在登记窗口时不接管用户窗口。未提交完成的修复不能被普通空白页识别逻辑当作可分配库存。

## 在指定窗口创建页面

本机 `Target.createTarget` 没有指定既有 `windowId` 的参数。本轮由单 owner 临时加载受限 Manifest V3 worker，通过 `Extensions.loadUnpacked` 和 `chrome.tabs.create({windowId, active:false})` 在精确窗口创建；不要求 `host_permissions` 或额外 `permissions`，操作完成后卸载本次临时扩展。[Chrome tabs.create 官方说明](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-create)定义了指定窗口及后台创建参数。

该机制已在隔离Chrome和本机实际专用profile中验证；后续不可用时保持缺页和检查结果，不回退到猜测活跃窗口、`window.open`、抢前台、系统鼠标或移动用户页面。共享模式仍不使用旧的整个 Chrome 关闭重启路径。
