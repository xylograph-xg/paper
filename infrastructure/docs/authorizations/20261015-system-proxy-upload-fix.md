# 原系统代理与上传恢复：同一授权的技术细化

沿用用户本聊天要求查清修复20页卡顿、网络与ZIP问题均需分析，并明确“所有权限都给”的授权。本文件记录实测后的工程选择，不冒称用户另行指定参数。第一阶段与首次对照证据保留于[原授权](20261015-twenty-page-upload-recovery.md)。

首次线上原PUT没有成功，结果按unknown保留且禁止回放；外部只读HEAD对照证明同样两台主机API直连失败、复用现有系统HTTPS代理可获得真实400响应。系统代理读取必须在原服务上下文，沙箱内空字典不能当作系统无代理。后续对照使用另一合法新材料的新epoch，跨epoch原材料意图继续阻断，绝不重试首次未知上传。

工程细化：

- API context严格复用macOS现有HTTPS代理和bypass，不修改浏览器/OS代理；PAC/自动发现/SOCKS-only等未核对线路拒绝试验。原DNS上传白名单、完整ZIP字节、原认证/头、TLS验证、零重试/重定向及真实响应守卫不变。不使用IP上传。
- 只有一次原PUT得到真实2xx、fulfill且原生附件完整结算后，才启用已验证传输处理后续合法新材料；每材料独立fsync reservation/intent，跨epoch读取原意图，已有意图不再外发；首次失败/unknown不自动晋级或再试。上传仍最多5页、同原线程/事件循环、固定20槽；模型发送仍串行且重新核对原有全部守卫。
- 原窗口确实结束、从未点击发送的原生上传，允许以同target原PUT终止事件，或精确原上传技术失败回执独立证明可取消，不要求旧进程本来没有持久保存的网络环形记录。P85、两轮真实同指纹、全部原材料/ZIP/提示/草稿、完整历史、完整归档及关闭前CAS全部保留；不能据旧失败回执捏造特定网络错误。未知附件PUT也只能在模型明确未发送、原客户端结束后归档关闭页面；该材料原传输意图永久保留并阻断重传，不能冒充模型已发送或已完成。
- 新owner初始化先归档上一owner网络投影，带原观测owner和historical标签保留旧事件；不把旧事件算作新上传。未知原PUT在核验恢复及领取处独立阻断，释放页面不等于允许重投材料。
