# 桌面按期刊分类的失败 DOI 清单

用户 2026-10-12 本聊天授权原文：

> 现在在桌面上生成一个按照期刊分类的拉取失败文件夹，内部是按照期刊分类的 doi 列表文件，后续我将手动拉取这些文献，其中要求每 2h 检索新增文献，然后根据拉取文献增加和删减这些 doi 列表

实现：[同步脚本](../../maintenance/sync_failed_dois.py)，默认输出 `/Users/xiaoyanhao/Desktop/拉取失败`。只读主 Catalog，一期刊一 txt、一行一 DOI，按现有期刊名分组，不猜测合并。失败包含 `needs_manual_download`、`needs_access_check` 和获取失败任务，成功以现有核对流程登记的 available、原文路径、哈希和非空文件为据。尚未尝试、无有效 DOI、身份版本待核对、范围外、勘误和人工排除不进入普通下载清单。

用户随后澄清“不是 codex 更新”。原 Codex 自动化已暂停；每两小时由现有 `local.paper.web-tab-watch` 本地后台运行脚本，扫描既有拉取/发现链路新增 Catalog 记录，不恢复暂停或另起发现/外发链路。手动 PDF 继续放入桌面“文献暂存”，现有流程核对登记后从清单移除。索引只清理脚本管理的 txt；用户修改先备份，用户 PDF 不删除。无需新增 LaunchAgent 或调整浏览器。

实际验证：隔离数据库新增、重复同步零新增、成功后移除、空期刊文件清理通过；初次桌面导出 16,595 个唯一 DOI、1,360 个期刊分组，跳过 75 条无有效 DOI 和 1 条保护记录。数据库与输出不纳入 Git。定时实际执行须由本地后台状态记录，不以创建自动化声称已长期运行。

用户同日补充“内部排名时间新的排前面”：每期刊内按文献发表日期降序，缺日期用发表年份，日期与年份都缺失置后，同时间按 DOI 稳定排序。明细保留原始发表日期/年份，不伪造缺失日期。
