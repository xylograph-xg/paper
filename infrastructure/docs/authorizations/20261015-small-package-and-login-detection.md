# 从头小包检查、每分钟统计与登录识别

用户在本聊天要求先检查20个网页，选择较小包从头检查，并每分钟统计当前状态。随后用户说明原3个保护页实际需要登录，并要求系统自己识别和指出登录页面，才能手动登录。

- 仅原唯一所有者读取已登记专窗的真实登录UI并标明原槽位；已知认证地址、可见登录控件/弹窗作为证据，文章与回答里的登录文字不作为证据。需要登录持久暂停新发送，保留原页、草稿、附件及未知回执，不自动登录或处理验证；用户处理后仍须原所有者实查，不能按时间自动解除。
- 当前聊天每分钟只读统计固定20页和本轮小包阶段，记录观测新鲜度与未知，不重复算旧事件。新建的当前聊天心跳仅做统计，不恢复另两个已暂停半小时诊断或退役实验，不增加LaunchAgent/CDP连接。
- 小包只选真实已授权队列中原文、冻结输入、材料及历史可核对者，由原所有者在发送门允许后处理，不为测试制造科学内容、不额外重发已发送或未知请求。选包与完成上传分别记录；登录未核对前不外发。
- 检查发现上传回调结束、原页已完成归档替换后，旧target不再进入健康快照，导致待证实上传名额不能释放。允许沿已确认原维护替换回执释放该旧名额，仅影响新合法材料资源，不改变旧请求结果。确认关闭、归档、登记CAS及新页ready保护继续，缺页或中间态不作释放证据。
- 通用修复、完整回归、接口及全局检查后，经原监督器正常交接；原暂停、登录、额度、科学/人工保护不解除。离线检查、实机登录识别、小包实际发送/上传/回答和独立最终验收分别记录。

用户随后要求“等待自动确认的直接刷新网页”。本轮绑定原02、08、16槽：只由原所有者在原提交锁内核对实时同窗口/槽位、无上传/生成/消息/草稿/附件/实际登录输入或验证码、原target全部历史明确未发送，且仍显示“浏览器检查未能完成，请重新加载”的页面，完整归档和账本CAS后刷新一次。不重新提交旧材料、不关闭/新建页面、不清除账户暂停。刷新意图先持久登记，导航回执未知不重复；页面状态已变或出现登录/验证则保留。刷新完成后重新只读区分恢复、登录和检查失败，用户仍自行登录。

用户随后明确“所有遇到的问题，都不手动处理，查找流程上的问题让他们能自己通过”，并要求修复旧页占据5个上传名额。技术恢复及恢复后核对由原流程自动完成。本轮明确刷新也接纳已恢复无错误输入框的原空白页，纯编辑器换行属于空白，非空草稿仍保护；阻断保存完整实时快照及具体字段，不仅给模糊“等待确认”。

仅user_report_current_chat或resident_dom_login_ui来源的观测账户门，在原专窗全部20个原target均有新鲜、同窗口、可见真实账户控件及可用输入框，且无登录/验证码/错误/额度UI时，经连续两次相隔至少30秒原所有者实查可解除。归属/指纹变化、观测缺失、用户暂停及其他来源人工门不解除。保留原控制事件、原暂停和科学保护，不输入账户凭据、不点击验证码、不假造登录成功。真实失效登录或验证码仍需网站授权会话完成；流程继续观察及定位，不冒称已通过。

用户随后确认“180合理”，保留180秒原生附件结算等待，不以放宽该时间处理本轮故障。原只读上传元数据补充成功响应和请求结束证据，以区分传输结束与原生结算；仍不得据HTTP 2xx单独点击发送或宣称附件/模型/科学验收成功。

本轮工程核对还发现，既有最低并行准入未计入被上传锁排除的原队上传target，导致三队在上传期间被反复按零占用比较，新制卡缺少核验分而长期排后。按已有8/4/3最低分配修正占用输入，使用原活动与上传target并集去重；不调整最低值、队内分数/FIFO、固定分组、180秒及最多5页上传，不将准备/上传冒称实际生成。

用户随后要求统计页面检查异常的槽位分布、成功率并处理同步与反复异常。观测层保持每10秒、原唯一所有者/连接和3秒状态读取、状态与收取分别5秒协程期限（实际墙钟耗时另记），改用单次DOM读取账户、停止按钮、当前assistant完成、回答数量、发送按钮禁用和上传指示信号，减少同轮多次浏览器往返。灰色发送按钮仅记未就绪证据，不据此判断实时上传；最后用户轮次的complete不能冒充assistant完成。已保存且无生成状态的页面跳过重复收取归属读取，仅减少观察负载，不授予复用/关页/发送权限。轻量状态先发布，归属/稳定性/收取独立检查；后者失败单列receipt诊断，不抹去先前成功状态，不冒称收取或身份核对成功。稳定性复查发现恢复生成时更新实际状态。真实失败保存唯一检查轮次、target、开始/结束、阶段与耗时，外层截止不丢失已有证据；错误日志不含URL、提示、正文或凭据。暂停、账户门、未知请求、回答完整保存/CAS和原健康守卫不改变。工程回归与线上改善分别记录，不保证这些改动解决上传线路故障。
