# 节点波动下的原工作流恢复（2026-10-15）

用户在本聊天要求“按照你的这些逐个修复”，并明确说明“固定没有用，都会波动”。此前用户报告同一79 MB ZIP在App上传一段时间后失败，切换节点后成功。该报告是用户观察，不冒充已采集的App请求或严格A/B结果。

本轮不固定代理节点、不扩大模型请求重试次数、不重发已发送或结果未知材料。保留专窗20槽、原唯一所有者、上传最多5页和原三个LaunchAgent。用户暂停、登录/验证、额度、人工决定、原文、冻结材料与完整原回答继续优先。

## 允许的工程修复

- 原所有者通过现有启动请求恢复已退出的专用Chrome。仅已明确就绪的旧启动、有效固定登记、原profile/端口对应进程不存在、端点不可达且相隔至少30秒两次实查成立时，归档旧请求和登记后生成一次新nonce；每小时最多2次、间隔至少5分钟。进程仍存活、启动/创建回执不明、部分初始化、登记损坏、暂停或人工验证时不另开。存续浏览器不被此路径关闭；旧材料账本不改写、不重发。
- 启动就绪检查使用原有有界页面快照中的输入框和错误证据，不为缺失输入框串行等待。当前主页错误提示的短文案“请重试，或退出登录后重新登录”须有真实UI来源；生成/上传/草稿/验证/额度和未知历史保护仍先执行。缺少可核对的错误来源时保留页面，不能标为健康。
- 尚处归档阶段、从未登记关闭/创建意图及候选的旧页面修复计划，若关闭前实查证据已变化，可核对原归档、账本和固定槽后逐字保存旧计划并取消该计划，让原页重新进入真实检查；不得沿用旧证据关闭页面。已登记关闭/创建意图、nonce或候选的未知操作继续保留，不能取消后重开；原请求及用户新草稿不改写。
- 原固定页、原上传意图所绑定PUT的真实HTTP/2、网络变化或连接中断接入既有五分钟网络冷却，仅限制新派发，观察和原会话收取继续。ERR_FAILED/ABORTED、未归因事件、HTTP拒绝不据此推断原材料未发送。网络错误不能缩短已有额度等待，冷却到期不宣称网站已恢复。
- HTTP-only watcher的本机CDP元数据读取显式绕过系统代理，仅允许本机端口；真实网站和上传继续沿用用户代理，不增加CDP连接。
- 403等HTTP错误仅额外保存白名单诊断头中的错误码和数字Retry-After，不读取/保存签名URL、认证、Cookie或响应正文，不由此自动重传。
