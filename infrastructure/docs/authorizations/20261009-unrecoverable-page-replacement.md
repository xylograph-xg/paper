# 不可恢复页面通用替换授权（2026-10-09）

用户原文：“这种后台处理不掉的直接关掉重新开一个”；随后澄清：“我是说所有后台流程处理不掉的页面，直接重开，不要特化，做成流程”。

授权扩大为原专用窗口内的通用故障页归档关闭补开，不限定文献、会话或槽位。健康检查每30秒安排，由原唯一所有者执行，提交锁忙时等待。持续120秒、60秒后的有界二次复核仍不可恢复的 unknown/saved_response_protected，原请求账本归属确定、完整实时观测、无上传/生成/登录验证/额度/草稿/附件挂起时进入兜底。已有完整回答优先收取、路径修复或逐字前缀补收；可收取者不进入兜底。

归档全量账本指纹及页面证据后，关闭前重新读取并核对同一故障指纹、账本、原窗口和槽位登记。复用持久替换日志，确认旧target关闭后以唯一nonce补回原窗口；补页回执未知只核对、不重复创建。每轮最多2页，不抢前台，不另建CDP连接或常驻入口。

关闭未知页面意味着可能放弃尚未取得的回答，不能证明请求未发送或服务器终止。旧账本与材料原样保留、原请求不自动重发、不补造科学结果。正在上传或生成、登录/访问验证、额度、用户草稿、归属不明、其他窗口仍遵循保护；这些是活动或访问边界而非本流程故障。暂停优先。页面证据无法归档或清单不完整时记录真实维护错误，不盲关。

实现：pipeline/shared_page_repair.py 的 stalled_page_fallback 与持久 _resume；配置 web_cards.shared_window.health_repair.replace_unrecoverable_pages=true、unrecoverable_after_seconds=120。关闭回执、补页回执和真实空白主页验证分别记录。
