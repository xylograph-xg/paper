# 上传提交与回答收取独立运行（2026-10-16）

用户本聊天原文：

> 现在 20 个并行，上传提交用一个，提取回答用一个，两个不影响，上传提交同步并行 5 个上线，传好就传别的窗口，提取回答检测到回答结束就提取

本轮实施：固定原专窗20页、唯一原后台所有者及一个CDP连接内，上传提交与回答检测/收取分别调度。上传提交最多5页并行，原生附件完整结算、原守卫发送及正式提交回执持久保存后立即释放该上传名额，不等待生成结束或下一轮全页维护；空出的名额继续领取其他合法就绪材料。领取确认及最终点击发送使用原共享提交锁；本页复用检查、导航、模型DOM设置、附件传输、发送就绪及点击后正式回执等待由各target独占并行，不把长等待放入全局锁。发送前仍核对实际模型/强度、原提示及全部材料守卫。回答由原观察器检测完成、核对原材料/唯一URL/提示、稳定正文及最终账本CAS后完整保存，不获取上传/提交锁；本地后处理只核对已经保存的原回答，不反复读取所有生成页。

“用一个”解释为原所有者内两个独立逻辑执行循环，不增加CDP所有者、浏览器窗口、常驻入口或跨线程操作Playwright对象。原事件循环的同步CPU工作仍可能带来延迟，不承诺物理资源完全隔离。

上传名额与原模型请求状态分开：失败或未知回调继续占位，直到原页新鲜完整无上传实查、已归档的原关页替换完成回执，或原所有者完整目标清单两次相隔至少30秒均确认旧target不存在。最后一种只释放全局上传容量；保存原target/回调结束时间/当前窗口epoch/两次检查时刻证据，不修改原请求账本、队列、未知状态、重试次数或原科学内容，不据此重发原材料。目标清单不完整、target重新出现、epoch改变或归档写入失败均不释放。

本轮20页派发、单所有者与正常验收后交接授权沿用本聊天已有授权；用户暂停、登录/验证码、额度、人工决定、源文献/版本/范围、未知提交与冻结输入保护持续有效。180秒附件结算阈值不变。不更换代理节点，不恢复暂停的聊天统计或其他实验。
