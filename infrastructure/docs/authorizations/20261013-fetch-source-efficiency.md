# 拉取来源调度与缓存改进授权证据

本聊天用户先要求：“深入分析我的拉取部分功能，并且在网络上查询相关的项目，旨在提升当前的拉取效率”。助手完成源码、账本和开源项目分析，提出“统一来源冷却 → 分来源退避及领取预检 → 共享缓存 → 补被引链 → 新全文来源对照”。用户随后明确：“继续”。

接续落实的第一批范围：发现/全文回退来源冷却一致、请求是否真正开始的证据、纯等待不消耗获取预算、新完整来源证据的独立重试安排、成功公开书目共享缓存、实际入队计数和诊断。沿用当前fetch入口，允许原worker排空后由原supervisor正常重载；不新增常驻入口。

不清空历史来源冷却、目标次数或终态；旧attempt缺少新观测字段时保留原处理。仅对本次有完整明确证据的未请求等待不增加次数。各来源权限和额度限制仍独立生效；较早复核整篇不等于提前探测仍冷却的来源。未知OSTI请求计数不推断为零。

缓存仅针对指定公开书目GET的HTTP200 JSON，至多24小时并尊重更短缓存头，不保存PDF、401/403/429、Cookie请求或密钥参数。已有原文、科学卡片、身份/版本/人工决定和暂停保持；OpenCitations/OpenAlex新全文生产通道本批尚未实测接入。
