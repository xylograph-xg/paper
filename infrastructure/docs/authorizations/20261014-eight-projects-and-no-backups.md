# 八项目归并、原服务维护与不保留数据备份

来源：当前聊天中的用户原话。用户澄清：“这些都是什么，我是希望把所有内容都拆进一些子项目中”。随后对明确列出data/config/docs/pipeline、维护原服务、更新路径并恢复原有状态的询问回复：“允许维护原服务，完成全部归并”。用户又明确：“之前有一个数据备份，删掉它，不需要备份”。

允许把全部源码、配置、正式运行存储、依赖和文档按八个顶层项目归并，原运行数据只移动真实目录，不改写冻结内容和科学证据。仅维护原fetch/web-cards/web-tab-watch三个常驻入口及原工作台/面板，恢复其原有状态；持久暂停优先，未知请求不重发，不新建浏览器窗口或增加CDP所有者。

已删除data/backups、data/recovery-backups和data/resident-backups中的备份副本，没有删除正式数据库、原文、卡片或回执。数据备份创建禁用，不创建替代数据备份。迁移候选只复制源码/静态测试材料用于离线验收，不复制生产数据。

旧授权文档、旧冻结JSON、原始回答和回执仍保留原字节。旧路径由公开WorkspacePath接口在读取边界解析，保留原hash和所有者归属证据。目录归并不表示科学验收通过。
