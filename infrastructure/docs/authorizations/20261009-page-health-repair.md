# 坏页自动检查与替换授权

用户先问（2026-10-09）：

> 现在这二十个里应该有不可用页面把

在确认各页问题需要分别核对后，用户明确要求：

> 有问题自动检查，删掉再新建

范围是[已授权共享专用窗口](20261009-shared-gpt-window.md)内、本任务20个固定槽位对应网页的健康检查，以及有充分原请求保护证据的故障页关闭和同槽位替代页创建。固定槽位编号保留，target可在完整检查、原证据归档和登记条件核对后替换，并保留原 target 历史。

这项最新授权允许对已发送但正式终止且没有回答的页面，在原材料/提示指纹、唯一正式会话、实时终止证据和不可变归档核对后释放并替换。它不授权重发原文献请求、清空未知账本、修改科学答案或把无回答记为成功。已有正式回答先完整收取，归档路径失配先恢复；临时会话、未知提交、活动生成、访问验证及归属不确定继续保留。

初始12个待核对槽位包括已有答案未收、归档路径失配、SSL明确未发送、8个正式会话无回答及1个临时会话回执未知，不等于12个都能自动删除。每页以实际材料、账本和实时证据决定，不以槽号或旧状态标签直接操作。

仅原 `web_cards` keeper 作为单 CDP owner执行，继续使用提交锁和固定20页上限。计划采用临时受限 Manifest V3 worker精确指定登记 `windowId` 后台创建，不猜测活跃窗口、不抢前台、不操纵其他用户页面；当前 Chrome 支持性和真实执行结果仍需实测。不可证明正确窗口时保留待检查，不声称新建成功。

不增加常驻服务，不解除用户暂停、登录验证或额度等待，不恢复旧评审循环、本地模型或其他暂停通道。原文献任务完成、科学核对通过和页面修复成功分别记录。生命周期、运行记录和验收范围见[坏页自动检查与替换](../坏页自动检查与替换.md)。

实机补充：初始诊断中的槽09后来核对为纯空assistant占位，旧观察程序错误保存0字节回答。它不是有效收取；保留原账本与空文件并阻止误排重试，仍按原正式请求稳定终止无正文规则归档替换。详见运行验收记录。
