# 分数排序、完整歧义报告的有限修正与工作台移窗（2026-10-09）

用户请求：“为什么他不在修正队列里，都按照文章分数排名排列，以及现在为什么全部卡住了”。承接已授权的问题自动处理，修复完整报告被整体歧义状态阻止修正的问题。工作台移窗的异步问题答复：“允许后台移出工作台页面”。

队列排序与精选库同源：真实文献质量＋同一卡片及原文版本的核验分降序；缺总分排后，再按质量、方向新颖性，同分保留入队时间/全局序号。配置queue_order=paper_score，不改入队证据，不抢占已领取、上传、发送或未知请求；8制卡/4核验/3修正固定预留继续，余5共享。核验和修正的准备、派发、展示与页内排队采用同一排序规则；新版分数须绑定新版，不借旧分。

完整检查、无missing_inputs且verdict=cannot_evaluate的报告，若重大问题有原文逐字证据及有效卡片字段路径，在partial_ambiguous_rework=true下进入已有原文重做队列。旧报告保留needs_user/cannot_evaluate语义，入队状态仅表示已交修正，不能视为通过。原文重做上限2次、完整原回答归档、原文/卡片/输入指纹、人工保护和暂停继续核对。纯歧义且没有有据重大问题继续保留。生成仍仅用原文与通用规则，不上传旧科学答案或报告定制答案，新版必须独立核验。

当前全停缘由是专窗出现21页，其中唯一非登记页为本地文献阅读工作台，触发正确的专窗20页及用户页保护。一次移窗只针对授权记录中的原target、唯一http://127.0.0.1:8767/页面和原windowId。唯一CDP所有者持提交锁，以临时worker chrome.windows.create({tabId,focused:false})移动原页，无新建标签页、导航或关闭，完成后卸载。回执未知只核对原target，不重复移动。其他窗口和非授权页面受保护。
