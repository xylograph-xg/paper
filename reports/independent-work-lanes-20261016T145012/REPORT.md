# 上传提交与回答提取独立运行

本轮落实用户要求：20个固定网页共享生成容量；上传提交独立调度，最多5页同时执行，成功后补下一页；原观察器独立检测结束并完整保存回答。

## 改动

- 原所有者增加合作式上传派发循环，仍使用同一个Playwright线程、事件循环及CDP连接；每0.5秒检查准入，一次可补足5个名额。队列领取仍核对原target、正式登记、暂停/额度、最低目标、文章分数与不可变FIFO。
- 成功上传、守卫发送及持久提交确认后立即释放上传名额；生成继续占网页，不占上传名额。失败和未知回调保留原保护。
- 两次相隔30秒的完整原连接目标清单确认旧target消失后，仅归档并释放上传容量，原未知请求、队列、原材料及重试计数不改变。清单不完整、epoch变化或归档失败不释放。
- 回答收取不再获取上传提交锁。保留原材料、唯一会话、实际提示、无生成、完成标记、稳定正文与最终账本CAS；原回答完整落盘后才进入本地后处理及页复用核对。
- 主循环不再重复读取全部生成页，只核对已经保存的回答；后处理中的target与新上传互斥，其他页面继续派发。
- 晚到的提交确认保留同一绑定下已经保存的回答，防止把`response_saved`改回`submitted`。
- 页面复用检查、导航、模型设置、发送就绪和点击后的正式回执等待均在原target独占下并行；共享锁只用于短暂暂停/领取确认及最终守卫和唯一点击，避免一页最长60秒的回执等待阻塞其他页。暂停保护先于任何页面检查，并在准备及发送前重复核对。

当前文档为实施记录，不是非实施方最终验收结论。180秒附件结算阈值、20槽、5个上传提交上限及原暂停保护不变。
