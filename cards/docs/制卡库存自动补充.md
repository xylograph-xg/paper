# 制卡精选不足时自动补充

2026-10-08用户澄清：不足的是制卡精选待办，补充来源是其他未进入制卡的文献，并非增加拉取种子。上一轮误解的下载文献补种子代码/配置已撤回；核对没有实际seed_auto_download提升事件。

主配置web_cards.refill_min_pending=20。优先沿用约30%元数据精选；可立即运行的queued待办少于20时，从已下载原文、从未进入web_card_jobs的其他文献按通用主题相关性、可信既有相关性、期刊、引用和年份排序补齐至20，候选不足时不虚造任务。selection_kind=downloaded_refill明确记录补充来源，不伪造文献质量评分。

历史完成、失败、未知提交、保护任务和未到重试时间任务均不当作可运行库存；这些任务不被重新排队。补充候选仍要求未有人工作出决定、无已有卡片、无身份/版本/范围问题；原文哈希必须一致，有历史attempt账本的候选不补充。保留专窗20页共享上限、制卡最低并行8页及所有提交/暂停保护；实际生成数取决于待办与实时会话核对。

每分钟页面检查进程在制卡允许运行时核对库存并调用同一原子选文事务，避免长附件上传延误补充；制卡主进程下次正常启动也使用同一规则。共享Catalog和数据库原子claim防止重复。无需打断正在生成的页面。
