# 审计报告目录

此目录集中保存 paper 整体项目及子项目的审计报告，以及 Codex 操作 Qoder 的本地手册。整个目录（包括 README 和手册）通过仓库本地 `.git/info/exclude` 排除，不纳入 Git；该排除设置不会随克隆传播。

操作标准见 [Codex 操纵 Qoder 手册](Codex操纵Qoder手册.md)。

## 报告文件命名

格式：`项目名_调用模型名称_编号_月日时分.md`

- 项目名：整体审计用 `paper`；局部审计用真实子项目名，如 `workbench`、`cards`、`fetch`、`review`、`correction`、`infrastructure`、`codex_desktop_chat`。跨组件问题按手册选择最近的共同项目根。
- 模型名称：写实际调用的模型，当前 Qoder 标准为 `Qwen3.8-Flash`，不能仅写应用名 Qoder。未经用户授权不得改用其他模型。
- 编号：位于模型名称之后、时间之前；每任务三个独立并行会话分别为 `01`、`02`、`03`。编号不是重试次数。
- 月日时分：北京时间（Asia/Shanghai）24 小时制 `MMDDHHmm`，固定八位，使用实际创建报告时刻。正文另记完整年份、时间、任务/批次标识、会话编号、调用应用、模型与推理强度。
- 分隔符为半角下划线 `_`，扩展名为 `.md`。文件名中的模型标识不得含路径分隔符或非法字符。

示例：

- `paper_Qwen3.8-Flash_01_10181600.md`
- `paper_Qwen3.8-Flash_02_10181600.md`
- `paper_Qwen3.8-Flash_03_10181600.md`
- `workbench_Qwen3.8-Flash_01_10181605.md`

## 不覆盖原则

- 报告生成阶段，每次独立审查新建一份报告，禁止覆盖、截断、追加、删除或改名已有报告。分析完成后的原件删除按下节执行。
- 用排他创建，例如 Python `open(path, "x", encoding="utf-8")` 或 `os.open(..., O_CREAT|O_EXCL)`；检查不存在不能代替排他创建。
- 若标准文件名已存在，保留原文件、会话编号和时间，在扩展名前增加冲突序号，例如 `workbench_Qwen3.8-Flash_02_10181605_dup02.md`；仍以排他模式创建，冲突则递增。`dup02` 仅表示命名冲突，不代表第四次审查。
- Prompt 必须指定本目录、命名规则和不覆盖原则。Qoder完成后应返回实际绝对路径。Codex默认在三个独立任务明确发送成功后结束，不等待报告；仅用户另行要求收取时实际读取文件、核对批次/会话标识和内容，不能仅凭模型声明认定报告收取成功。

历史报告保持原位、原名、原字节；不追溯重命名。本目录内 README 和操作手册是管理文档，不采用审计报告文件命名。

## 分析完成后的原件清理

- 用户要求分析审计报告后，完成对应报告的阅读、分析与结果交付，即删除本目录内已分析完毕的分析 MD 文件原件，不另存原件副本。
- “分析完毕”指已完成用户要求的分析并交付结论；仅发送任务成功、模型生成完毕、报告下载/落盘或文件读取成功均不等于分析完毕，不能提前删除。
- 按本次实际分析的文件逐一删除；尚未分析、仍在生成或分析未完成的报告保留，不按扩展名或目录批量清空。
- README、Codex操纵Qoder手册及其他管理文档不属于待删除的分析报告；目录外历史报告、原科学核验报告、原文、卡片、冻结输入及请求回执不适用本条。
- 此规则是对已分析原件的后续清理授权，不改变报告生成期间的不覆盖原则，也不触发当前现有文件的立即删除。
