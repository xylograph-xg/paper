# 文献方向自动标签与主题学习集合

独立物理子项目 `literature`，包 `paper-literature` 0.7.0。**一级、二级分别获授权进行全库后台自动候选标注，各8个独立Python进程、独立暂停。** 一级只使用标题和摘要；二级复用可验证的原文逐页文本，缺失时可显式补本地PDF文本解析。没有网页上传或本地大模型推理；一级后台不新增LaunchAgent或CDP连接。

逐篇人工打标签及人工确认入口已停用：HTTP/CLI/Library的`annotate`明确拒绝，Store拒绝新增manual来源。历史人工决定和证据保留；自动输出不覆盖历史人工拒绝或弃用词表。

## 自动标注流程

1. 经core公开只读接口读取元信息、原文身份及原任务材料指针，不构造Catalog或读取旧科学卡片答案。
2. 核对当前PDF字节hash、任务文献/原job身份、原文账本hash和冻结context文件hash。只读取source_text原文；旧模板、scientific_rules、旧答案和评分不进入分类输入。
3. 一级在标题/摘要内使用受控词表、别名和研究语境；二级区分正文/方法/讨论/参考文献以及实际使用、背景提及、否定。
4. 原文使用固定规则选择证据窗口，默认上限14,000字符，保存覆盖页及截取范围；它不是全篇科学审查。标签保存逐字原句、物理页、块ID及字符区间，发布前校验一致性。
5. 每个文献/输入/规则版本保存不可变运行结果和完全相同的输入。元信息或原文变化后，旧标签不继续冒充当前结果。只有证据不足则保存无法判断，不创建人工标注任务。

SI-only的独立来源防护检查原文文本的封面页；Supporting Information/S1不能仅因文件hash相同就当主文。此时一级仍可运行，二级保留缺失/来源问题，不改写原材料或主库。

当前受控词表有53个标签，覆盖有机发光/OLED、TADF/MR-TADF、磷光、激基复合物、AIE以及若干对象、问题、机制和方法。规则和词表有明显覆盖边界，实测结果见下文；不能把自动证据校验当科学核验。

## 核心标签策略

`directions-rules-1.4.33` / `core-directions-v2`通常显示一级1～3个、二级2～5个核心标签；数量仅供参考，不凑数、不硬截。一级优先具体研究方向，主题明确时不重复显示泛泛的分子/薄膜对象；二级保留主线对象、机制、问题及有辨识度的方法，常规测量移入辅助证据。没有充分证据可以少于范围，多主题证据充分可超过范围。

`classify(document)`仍只读传入的同一输入，无文件/网络/模型副作用。返回`level1`/`level2`为核心标签，`supporting_labels`为辅助证据，`inherited_labels`为核心标签继承的上位分类，另有`selection_policy`和`count_guidance`。全部记录都校验逐字引文并保存；列表只显示核心，详情保留其余内容；标签和集合筛选采用核心及其上位分类，不因常规表征就归入研究主题。自由文本检索仍会命中原始标题/摘要。

侧库使用新规则版本生成独立run，旧结果不改写；旧自动结果需显式重新运行才使用新策略。对当前文献输入变化的保护同时覆盖核心、辅助和继承分类。候选工作台依赖声明为paper-literature==0.6.0，旧服务需正常重启加载，当前任务没有重启常驻工作流。

同原10篇开发样本的核心参考标准评测：一级P=81.25%、R=59.09%；二级排除已知SI-only材料，9篇P=64.29%、R=23.68%。新旧预测都对同一核心标准比较；不与前次宽标签标准直接比较百分比，不称为新独立测试。结果说明精简有效、关键方向覆盖仍不足，详情见[核心标签试验](../reports/20261020-core-directions-evaluation.md)。

## 使用

现有工作台顶部“标签与主题学习”进入 `/literature`。文献提供“运行一二级标注”，也可勾选最多100篇自动处理；已经运行的旧工作台需正常重启加载新代码。页面保留元信息、证据查看、多维筛选、词表维护、集合动态规则、人工加入/排除、主题内角色/顺序/进度和笔记；集合编排不是逐篇人工打标签。

```sh
PYTHONPATH=infrastructure/bootstrap:. infrastructure/environments/test/bin/python -m literature \
  --catalog /绝对路径/catalog.sqlite3 auto_label <<'JSON'
{"paper_ids":["真实文献ID"],"fallback_pdf":false}
JSON
```

```python
from literature.api import Library
library = Library('/绝对路径/catalog.sqlite3')
result = library.auto_label(['真实文献ID'], fallback_pdf=False)
# 没有可复用文字层时，明确传True才调用read公开的本地PDF解析，不调用模型。
```

`auto_label`每次1–100个ID；单篇本地持久化、重复同输入运行ID不变。HTTP每次1MiB，复用工作台 Host、访问模式和同源 Origin 检查；校验400、版本冲突409、存储错误503；客户端不自动重试写入。主Catalog只读连接等待3秒，侧库事务等待5秒。本地文件hash和PDF解析耗时依实际材料大小，不冒称全流程硬超时。

## 存储及其他能力

默认侧库位于主Catalog同目录`literature.sqlite3`，可显式指定独立位置，禁止与主库重合。

| 表 | 内容 |
| --- | --- |
| vocabulary / aliases | 稳定标签、别名、维度、候选/正式/弃用、最多三层父子结构 |
| evidence / decisions / events | 旧证据和决定、自动候选及历史保护；不开放新增人工标签 |
| automatic_runs / automatic_inputs / automatic_heads | 不可变一二级自动输出、同输入冻结文本及当前索引 |
| collections / members | 学习目标、问题、动态筛选、加入/排除、角色、顺序、进度和笔记 |

元信息、来源keywords、文献质量及核验分继续读原记录。普通检索覆盖全登记文献，不受约30%制卡比例限制；精选/精读准入不变。自动标注状态为automatic，表示规则证据校验，不等于科学核验通过。对历史手工决定、弃用术语的保护持续生效。

冻结Python基线：一级P=100%、R=54.72%、F1=70.73%；二级P=81.08%、R=41.10%、F1=54.55%。词表内召回分别67.44%和73.17%。这是10篇诊断样本和助手参考标准，不代表全库准确率或外部专家验收。SI-only保护是在发现来源问题后单独加入的通用安全修复，未回改冻结基线或按样本增加科学规则。
